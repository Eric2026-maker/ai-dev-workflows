# Codex Browser Plugin Use Case

这一期推荐的 Codex 插件：

> Browser 插件：让 Codex 打开本地页面，做真实的前端验收。

## 为什么推荐

很多 AI 编程流程只停在“生成代码”和“跑测试”。

但前端有一类问题，代码看不出来：

- 移动端文字溢出
- 按钮不可点击
- 弹窗被遮挡
- 表单交互异常
- loading 状态不对
- 页面在真实浏览器里空白

Browser 插件的价值是：

> 让 Codex 像 QA 一样打开页面、点击、截图、检查布局，而不是只读代码猜结果。

## 适用场景

- 本地前端页面验收
- 响应式布局检查
- 表单流程测试
- 登录/搜索/筛选等交互测试
- 截图回归检查
- AI 生成 UI 后的视觉确认

## 推荐工作流

```text
写代码 -> 启动本地服务 -> Browser 插件打开页面 -> 点击/截图/检查 -> Codex 修复问题
```

## 示例 Prompt

```text
请使用 Browser 插件打开 http://localhost:3000。

检查：
1. 首页是否正常渲染
2. 移动端 390px 宽度下是否有文字溢出
3. 主要按钮是否可点击
4. 表单提交是否有反馈
5. 是否有明显遮挡、空白或错位

如果发现问题，请回到代码里修复，并再次用 Browser 验证。
```

## 为什么它适合程序员

它不是让 AI “凭感觉改 UI”。

它让 AI 多了一个观察渠道：

- 代码是一个视角
- 测试是一个视角
- 浏览器真实渲染是另一个视角

前端任务里，这个视角非常重要。

## 输出物

一次完整 Browser 插件验收，至少应该输出：

- 检查过的 URL
- 桌面端结果
- 移动端结果
- 发现的问题
- 修复的文件
- 二次验证结果

## 关键原则

不要只让 Codex 写页面。

要让 Codex 打开页面，看页面，点页面，然后再改页面。
